# PS5 Relapse (7.00–13.60) Host Entry

**Date:** 2026-09-30
**Status:** Implemented, no hardware validation yet (no PS5 available to this agent)
**Scope:** New `ps5-relapse/` directory only. Does not touch `ps5/` (the existing
GamerHack shortcut entry, still routed for PS5 1.xx–5.xx), any PS4 engine, or
any shared file (`style.css`, `i18n.js`, `i18n/*.js` gain new keys only,
nothing existing is edited).

## Why

Cross-repo decision record:
`ludora-ps4/docs/research/2026-09-30-ps5-hen-selection-and-13.60-site-support.md`.
Summary: the PS5 route this repo has shipped so far (`ps5/`) only ever covered
firmware 1.xx–5.xx via an external GamerHack shortcut `.pkg`, and its
`index.html` in the packaged output is a placeholder string written directly
by `ludora-site`'s `scripts/package-jb-host.mjs` — there was no real exploit
chain behind it for higher firmware. `ntfargo/Relapse-Exploit` (MIT, pinned at
commit `22c56be255ce79eee23cf8f1b1f10b63c5da8f24`, 2026-09-30) is a public,
in-browser WebKit + kernel exploit covering PS5 firmware 7.00 through 13.60 on
a fixed, discrete list of 33 firmware versions (not every 0.01 step in that
range — see `ps5-relapse/src/firmware.js`'s `supportedFirmware` array, which
is the actual gate and must stay the single source of truth for exactly which
firmware strings are supported; do not derive a continuous-range approximation
of it anywhere, including in `ludora-site`'s routing table).

## What was vendored, unmodified

Copied byte-for-byte from the pinned commit, at the same relative paths
Relapse's own `index.html` expects:

- `src/*.js`, `src/utils/*.js` — the exploit chain itself.
- `offsets/*.js` — 33 exact per-firmware offset tables.
- `payloads/elfldr-ps5-1360.elf`, `payloads/kexp_2026_05_25.bin`.
- `UPSTREAM-LICENSE` — the upstream MIT license text, kept for attribution
  (this repo has no established per-engine LICENSE convention today, but
  MIT requires the notice travel with copies of the code, and this is the
  first host entry in this repo built from an MIT-licensed upstream rather
  than a GPL patch-stack source).

None of these files are edited. Do not add Ludora branding, i18n, or logging
hooks inside them — see `ludora-bridge.js`'s header for why and how the
presentation layer stays entirely outside upstream's files instead.

## What is new (Ludora's own files)

- `index.html` — Ludora's own page shell (brand bar, ad slot, status line),
  built the same way `zrm/index.html` and `13x/index.html` are: our HTML,
  upstream's unmodified scripts loaded in upstream's own script-tag order.
  The one hard constraint: `<div id="console">` must exist verbatim, because
  the vendored `src/site.js` does `document.getElementById("console")` at
  module-evaluation time — renaming that id breaks the unmodified engine.
- `relapse.css` — adapted from `../zrm/zrm.css` (same visual system), with
  `#out` renamed to the required `#console` and the AppCache-progress-only
  rules dropped (see "No AppCache" below).
- `ludora-bridge.js` — a `MutationObserver` on `#console` that mirrors the
  upstream engine's own log lines into `#state`/`#det`, without importing or
  calling into any upstream file. This is the same technique already used for
  `13x/jb.js` (an unmodified upstream engine observed via
  `body.className`) — extended here to observing DOM text instead. Success
  and failure classification is based on exact literal strings read directly
  out of the vendored `src/main.js` / `src/site.js` (not guessed); see the
  file's own header comment for the three cases (`unsupported firmware`,
  `error`, `success`) and the fail-open-to-raw-log behavior if upstream ever
  changes those strings. The raw log in `#console` is never hidden — the
  bridge only adds a summary on top, honoring the decision doc's rule that
  the page must not claim success (or failure) before the payload itself
  reports it.

## No AppCache for this entry (explicit, not an oversight)

Every PS4 engine in this repo ships a `cache.appcache`/`.manifest` because
PS4's Application Cache lets the console's offline "Access Browser" replay a
cached page without a live network connection — a PS4-specific browser
limitation. There is no verified evidence PS5's browser needs, or even still
implements, the deprecated AppCache API, and the existing `ps5/` placeholder
entry in this repo has never carried a `manifest=` attribute either. Rather
than guess and risk shipping a stale-cache bug (already a recurring, real
failure mode across every PS4 engine in this repo whenever a manifest is
wrong), `index.html` has no `manifest=` attribute at all. This is listed as
an open item for real-hardware verification, not assumed settled.

## Verification done without hardware

- `npm run verify:host-pages` / `npm run verify:host-runtime` — pass (47
  pages total; the new page's local stylesheet, all `src=`/`href=`
  references, and the absence of a manifest reference are all checked
  generically, no code change needed to those scripts).
- `npm run test:host` — pass, unaffected (existing tests are engine-agnostic).
- `node --check ludora-bridge.js` — syntax valid.

## Explicitly not done here (tracked in the cross-repo decision doc)

- No real-hardware run of the exploit chain itself.
- No verification that `onionHEN` (Ludora's chosen HEN, see the decision doc)
  actually loads correctly once Relapse's `elfldr` on port 9021 is up, or
  that it works at all on the same firmware set as this entry.
- No decision yet on whether PS5's browser needs the old-WebKit style
  workarounds (`ConsoleBaseStyles`-equivalent hand-rolled CSS instead of
  Tailwind) that PS4 `/jb` pages need on the `ludora-site` side — irrelevant
  to this repo's plain-CSS pages, but relevant to `ludora-site`'s own
  `/jb`/`/jb/provision` pages once a real PS5 device is available.
